# 固定模板解析与人工校正

当前状态：角色卡片识别功能已删除，账号只允许手动录入或JSON导入。本文件的角色卡片段仅保留历史版式记录，不代表现行上传接口。DPS图通过 `scripts/reparse_dps.py` 与独立头像库离线识别，经完整视觉转录后，由 `scripts/build_reference_database.py` 显式转换为计算配置；原始OCR不直接进入优化器。

本文档记录已检查过的两张固定模板原图。它只定义切图、锚点和人工确认流程，不把截图中的账号或 DPS 数值直接提交为公共数据库。

## 角色卡片模板（1000 × 2601）

卡片底图卡位已经按原图像素核对。`data/templates/account-card.json` 保存这些坐标及归一化形式：

- 卡片底图左上角依次约为 `x = 46, 231, 416, 601, 786`，卡位宽约 171；
- 卡片底图顶边依次为 `y = 851, 1062, 1272, 1483, 1693, 1904, 2115, 2325`，卡位高约 194；
- 前 7 行每行 5 个卡位，最后一行仅第 1、2 列有卡片；
- 武器图标浮层会越过底图左边和底边，不能用底图矩形裁掉；共鸣链文字浮层在右下方，不能与武器阶级文字混为一项。

每个卡位按以下顺序生成草稿：

1. `level`：左上角的 `Lv.*`，可做小范围数字 OCR；未知时保留 `null`。
2. `element`：右上角圆形属性图标，使用图标匹配；不从颜色猜角色名。
3. `character_id`：卡片没有角色名字文字，使用头像/立绘模板匹配生成候选，必须人工确认。
4. `weapon_id` 与 `weapon_rank`：左下浮层只有武器图标和可能的 `一阶` 至 `五阶` 字样；武器名称和实体数量不能从当前装备图标可靠推出，必须人工确认或补录。
5. `resonance_chain`：右下文字为 `零链` 至 `六链`；和武器阶级分开保存。

角色截图只表示“当前装备”，不表示仓库中同名武器的总数。当前按用户新要求简化：确认页每个角色只提供专武“无 / 精1～精5”，不展示独立武器库存编辑器。非零选择由后台转换为一把对应专武；多队计算仍检查武器占用。图片中未装备的专武由用户在该角色行补选。

无法可靠识别的专武不作为已确认库存。为了让识别稿可在当前下拉表单中编辑，可以预填候选值（未见精炼文字时暂填精1、未匹配到专武时暂选无），但必须保留逐行说明与 `needs_confirmation`，并撤销整体人工确认状态。候选值不代表精炼已核实或仓库确实没有专武；确认前页面不能直接计算。

账号头部包含 UID、账号名、日期和概览统计。UID 以及账号名属于隐私字段：V1 解析结果默认不持久化、不写入公共 DPS 数据、不上传到第三方识别服务；如前端需要展示，可仅保存在当前浏览器状态或本次请求内。

## DPS 长图模板（3974 × 14756）

长图上半部分是口径说明、评价标准和难度/稳定性图例。后半部分按版本区段排列若干配置面板。面板数量、每行列数和面板高度会变化，不能把整张图当成固定的规则表格。

已按整行深色分隔条确认以下区段。像素端点均来自原图，JSON 中同时保存归一化 `y` 值：

| 区段 | 内容区像素行（含端点） | 分隔条（含端点） |
| --- | ---: | ---: |
| 口径说明 | 0–1850 | 1851–1893 |
| 3.0下 | 1894–3067 | 3068–3109 |
| 3.0上 | 3110–6174 | 6175–6217 |
| 2.0下 | 6218–8291 | 8292–8334 |
| 2.0中 | 8335–10411 | 10412–10454 |
| 2.0上 | 10455–12538 | 12539–12580 |
| 1.0 | 12581–14717 | 14718–14755 |

这些行是可靠的模板锚点；面板边界目前只作为候选检测结果，不放进“已确认矩形”集合。每个面板通常包含：

- 左侧角色头像条；
- 配置名、作者/校对者、视频号或备注；
- 两个标签。图中红字明确说明“左侧为难度，右侧为稳定性”，所以左标签才映射到 `低 / 中低 / 中 / 中高 / 高`，右标签另存为 `stability`；
- 一个或多个数据表。主 C 表头可见 `配置 / 全队 / 单人 / 提升(前)`，辅助位表头常见 `链子 / 全队 / 单人 / 提升率`。行标签混合共鸣链和武器精炼（如 `0链`、`6链`、`5精` 等），不能假定所有表格的行集合相同；
- 面板底部的白色备注块。备注可能改变轴的适用条件或说明操作复杂度，不能把它当成 DPS 数字。

解析器应保留原始字符串、解析后的可选数字和来源矩形。`全队`、`单人` 和提升列的单位、缩放及统计口径以数据版本说明为准；固定模板解析阶段不得将图片读数擅自乘除或合成新的公共数据。无法可靠读取的单元格进入人工修正队列。

## 统一解析流程

1. 检查 MIME、像素数量、宽高比，并用模板标题/区段锚点做二次匹配。
2. 用 `data/templates/*.json` 的归一化坐标生成裁剪草稿；尺寸发生缩放时只按原图宽高等比换算。
3. 识别器输出每个字段的候选、原始文本、来源矩形、置信度和警告。低置信度、缺失字段、重复武器和不认识的头像一律标记 `manual_required`。
4. 当前账号由用户手工输入，专武新选项限无/精1/精5。DPS展示完整原图、65表824行原文与已映射覆盖。高配行累计继承，未标精炼的“专”按精1，当前64表811端点进入计算库。
5. 账号图片与 DPS 图片分开确认。账号状态可只留在浏览器或短期请求中；公共 DPS 数据只能由维护者导入的结构化 JSON 更新。

离线DPS OCR和格线候选工具已实现；人工转录单独保留并优先应用。配置转换会排除缺难度、缺数值或累计配置没有变化的来源项，不估计缺失DPS。详细装备基线假设、条件列口径及非抽卡形态处理见README和计算库metadata。
